Annex

D. Glossary

Every PostgreSQL term this course uses, in alphabetical order, each in one or two sentences, with the lessons where it is explained. Ordinary SQL words (SELECT, JOIN) are in annexes A1 to A5 rather than here.

A · B · C · D · E · F · G · H · I · J · L · M · O · P · R · S · T · U · V · W · X

A

TermMeaningLessons
ACLAccess control list: the array of privileges stored on an object, written like role=arwd/grantor. aclexplode turns it into rows.4, C
Advisory lockA lock on a number that your application chooses, not on a row or table. PostgreSQL only tracks it; what it protects is up to you (for example, “only one worker runs this job”). Taken with pg_advisory_lock or pg_try_advisory_lock.16
AutovacuumA background process that runs VACUUM and ANALYZE on tables automatically when enough rows have changed. It removes dead tuples, keeps statistics fresh and prevents transaction ID wraparound.17

B

TermMeaningLessons
BackendThe server process that serves one client connection. Every connection gets its own backend, which is why connections are expensive.1, 26
BloatSpace in a table or index that holds dead or empty row slots instead of live data, so the object is larger than its data needs. Caused by updates and deletes that vacuum has not yet cleaned up or cannot reuse.17
BRINBlock Range INdex: a tiny index that stores the minimum and maximum value for each range of table pages. Useful for huge tables whose values follow the physical order, such as an append-only timestamp column.12
B-treeThe default index type. A sorted tree that answers equality, range, sorting and prefix queries.12

C

TermMeaningLessons
CheckpointThe moment when the server writes all changed pages from memory to the data files, so that crash recovery only has to replay WAL from that point on. Too-frequent checkpoints cost I/O; too-rare ones make recovery longer.22
ClusterOne PostgreSQL server instance and its data directory: a set of databases served by one postmaster on one port. Not a group of machines; roles and tablespaces are shared across the whole cluster.1, 2
ConstraintA rule the database enforces on every write: NOT NULL, CHECK, UNIQUE, PRIMARY KEY, FOREIGN KEY or EXCLUDE.7, A5
CTECommon table expression: a named subquery written with WITH name AS (…) before the main query.8, A4

D

TermMeaningLessons
DatabaseA named collection of schemas inside a cluster. A connection is always to exactly one database, and a query cannot read tables from another database directly.2
DeadlockTwo or more transactions each waiting for a lock the other holds, so none can continue. PostgreSQL detects it after deadlock_timeout (1 s by default) and cancels one of them with deadlock detected.16, E
Dead tupleAn old row version that no running transaction can see any more, left behind by an UPDATE or DELETE. It takes space until vacuum removes it.15, 17
Default privilegesPrivileges that will be granted automatically on objects a role creates in the future, set with ALTER DEFAULT PRIVILEGES. They do not change existing objects.4
DomainA named data type built on an existing one, with optional constraints, such as create domain email as text check (value like '%@%'). Every column of that domain gets the same rule.6

E

TermMeaningLessons
EnumA data type with a fixed, ordered list of allowed values, such as shop.order_status. Adding a value is easy; removing or renaming one is not.6
EXPLAINThe command that shows the plan the planner chose for a statement. EXPLAIN ANALYZE also runs it and reports real row counts and times.13
Expression indexAn index on the result of an expression rather than a plain column, such as lower(email). A query uses it only when it contains the same expression.12
ExtensionA packaged set of SQL objects (types, functions, operators, index methods) installed into a database with CREATE EXTENSION, such as pg_stat_statements or pg_trgm.26

F

TermMeaningLessons
Foreign keyA constraint saying that a column's value must exist as a key in another table (or the same one). It can also say what happens when the referenced row is deleted or updated.7, A2
FunctionA named piece of code stored in the database, written in SQL, PL/pgSQL or another language, that takes arguments and returns a value or a set of rows. It runs inside the calling statement's transaction.18

G

TermMeaningLessons
Generated columnA column whose value is always computed from other columns of the same row, such as total numeric generated always as (qty * price) stored. You cannot write to it.7
GINGeneralized Inverted iNdex: an index that maps each element inside a value (each array element, JSONB key, or word) to the rows that contain it. Used for arrays, JSONB and full-text search.10, 11, 12
GiSTGeneralized Search Tree: an index framework for data that overlaps or nests, such as ranges, geometric shapes and nearest-neighbour searches. It backs exclusion constraints.12
GrantThe GRANT command, which gives a privilege on an object to a role, or makes one role a member of another. REVOKE takes it back.4
Group roleA role that does not log in (NOLOGIN) and exists to hold privileges for its members. Not a separate kind of object, just a role used that way.3

H

TermMeaningLessons
HOT updateHeap-Only Tuple update: an update that puts the new row version on the same page and changes no indexed column, so no index needs a new entry. Much cheaper than a normal update.17

I

TermMeaningLessons
Identity columnA column that takes its value from an automatic sequence, declared generated always as identity (or by default). The standard replacement for serial.7, A5
IndexA separate structure that lets PostgreSQL find rows by a value without reading the whole table. It speeds up reads and costs space and time on every write.12
Isolation levelHow much a transaction is protected from changes made by concurrent transactions: READ COMMITTED (the default), REPEATABLE READ or SERIALIZABLE.15

J

TermMeaningLessons
JSONBA binary JSON data type that stores parsed JSON, supports indexing with GIN and has operators for containment and paths. Prefer it to the text-based json type.10

L

TermMeaningLessons
LISTEN / NOTIFYA simple message channel inside PostgreSQL. A session runs LISTEN channel; another runs NOTIFY channel, 'payload', and listeners receive it when the sender's transaction commits.19
LockA claim a transaction holds on a table, row or other object to stop conflicting operations. Most locks are taken and released automatically.16
Login roleA role with the LOGIN attribute, which may open a connection. What other systems call a user.3

M

TermMeaningLessons
Materialized viewA view whose result is stored like a table and only updated when you run REFRESH MATERIALIZED VIEW. Fast to read, stale between refreshes.18
MVCCMulti-Version Concurrency Control: instead of overwriting a row, an update writes a new version, and each transaction sees the versions that were committed when its snapshot was taken. That is why readers do not block writers.15

O

TermMeaningLessons
OwnerThe role that owns an object, usually the role that created it. The owner may alter or drop it and grant privileges on it, regardless of grants.3, 4

P

TermMeaningLessons
Partial indexAn index with a WHERE clause that covers only some rows, such as where status = 'pending'. Smaller, and used only by queries whose condition implies it.12
PartitionOne piece of a partitioned table. Rows are routed to partitions by a key (by range, list or hash), and queries that filter on the key skip the partitions they do not need.20
pg_hba.confThe host-based authentication file. Each line says, for a connection type, database, role and client address, which authentication method to use. The first matching line wins.3, 5
PITRPoint-in-time recovery: restoring a base backup and replaying archived WAL up to a chosen moment, such as just before a mistaken DELETE.23
PlannerThe part of PostgreSQL that chooses how to run a query, by estimating the cost of possible plans from table statistics. Also called the optimizer.13
Plan nodeOne step in an execution plan, such as Seq Scan, Index Scan, Hash Join or Sort. Nodes form a tree; each one feeds rows to its parent.13
PolicyA row-level security rule on a table: a condition that decides which rows a role may see (USING) or write (WITH CHECK). Created with CREATE POLICY.5
PostmasterThe main server process. It listens for connections and starts a backend for each one, plus the background processes.1
PrivilegeA right to do one thing to one object, such as SELECT on a table or USAGE on a schema. Granted to roles.4
ProcedureLike a function, but called with CALL, returns no value, and may COMMIT or ROLLBACK inside its body.18
PublicationIn logical replication, the set of tables (and kinds of change) that a server offers to send, created with CREATE PUBLICATION.24
public schemaThe schema every new database has, first or second on the default search_path. Since PostgreSQL 15, ordinary roles can no longer create objects in it by default.2, 5

R

TermMeaningLessons
Replication slotA server-side record of how far a replica or subscriber has consumed the WAL, so the primary keeps the WAL it still needs. An abandoned slot keeps WAL forever and can fill the disk.24
RoleThe only kind of account in PostgreSQL. A role can log in, own objects, hold privileges and be a member of other roles. Roles are cluster-wide.3
Row-level securityA table feature that filters which rows each role can see and change, using policies. Enabled with ALTER TABLE … ENABLE ROW LEVEL SECURITY; abbreviated RLS.5

S

TermMeaningLessons
SchemaA namespace inside a database that holds tables, views, functions and types. Two schemas can each have a table with the same name; you tell them apart as schema.table.2
SCRAMSCRAM-SHA-256, the password authentication method PostgreSQL uses by default. The server stores a salted verifier, never the password, and the password is never sent over the connection.3, 5
search_pathThe list of schemas PostgreSQL searches, in order, for a name written without a schema. The default is "$user", public.2, E
Sequential scanReading a table from start to end, page by page. The fastest way to read most of a table, and the slowest way to find a few rows in a big one.13
Serialization failureAn error (SQLSTATE 40001) raised when, under REPEATABLE READ or SERIALIZABLE, a transaction cannot be completed without breaking the isolation guarantee. The correct response is to retry the whole transaction.15, E
Shared buffersThe server's own cache of table and index pages in memory, sized by shared_buffers.1, 21
SnapshotThe set of transactions whose effects a statement or transaction can see. It decides which row versions are visible under MVCC.15
StatisticsPlanner statistics: a summary of each column's values (most common values, histogram, null fraction) gathered by ANALYZE and stored in pg_statistic. Not to be confused with the activity counters in pg_stat_*.13
SubscriptionIn logical replication, the receiving side: a connection to a publication on another server that copies its changes into local tables. Created with CREATE SUBSCRIPTION.24
SuperuserA role with the SUPERUSER attribute. It bypasses every privilege check, including row-level security, and can run operating-system commands through COPY … PROGRAM. The course container's postgres role is one.3

T

TermMeaningLessons
TablespaceA directory on disk where PostgreSQL may store tables and indexes, letting you put some data on a different disk. Rarely needed on modern storage or in the cloud.2
Template databaseThe database copied to make a new one. CREATE DATABASE copies template1 by default; template0 is the pristine fallback. The course keeps shop_template for the checker.2
TOASTThe Oversized-Attribute Storage Technique: values larger than about 2 kB are compressed and/or moved to a side table automatically, so a row stays small. It is why a wide text or jsonb column works without you doing anything.6
TransactionA group of statements that succeed or fail as a unit, between BEGIN and COMMIT (or ROLLBACK). Without BEGIN, each statement is its own transaction.15, A5
TriggerA function the database runs automatically before or after an INSERT, UPDATE, DELETE or TRUNCATE, for each row or once per statement.19

U

TermMeaningLessons
UserIn PostgreSQL, a role that can log in. CREATE USER is exactly CREATE ROLE … LOGIN; there is no separate user object.3

V

TermMeaningLessons
VACUUMThe command that removes dead tuples so their space can be reused, updates the visibility map and freezes old rows. Plain VACUUM runs alongside normal traffic; VACUUM FULL rewrites the table under an exclusive lock.17
ViewA stored query that you can select from like a table. It holds no data of its own; each query against it runs the stored query.18

W

TermMeaningLessons
WALWrite-Ahead Log: the journal in which every change is recorded before the data files are changed. It makes commits durable, drives crash recovery and is what replication and PITR replay.22, 23, 24
WraparoundTransaction IDs are 32-bit and reused in a circle. Old rows must be frozen by vacuum before the counter comes round, or PostgreSQL stops accepting writes to protect the data.17

X

TermMeaningLessons
xmaxA hidden system column holding the ID of the transaction that deleted, updated or locked this row version; 0 when nothing ever did. A non-zero xmax on a live row usually means a lock or an update that was rolled back. Together with xmin it decides which snapshots see the row.15
xminA hidden system column holding the ID of the transaction that created this row version. You can select it: select xmin, * from shop.products.15
