B. psql cheat sheet

psql is PostgreSQL's command-line client. Besides sending SQL, it has its own commands that start with a backslash, called meta-commands, and settings you can change on the fly. This page lists the ones you will actually use, each with an example. Every command here was run against the course's PostgreSQL 18 container.

Start and stop

In the course, ./pg psql opens psql inside the container, connected to the shop database as the superuser postgres. ./pg psql other_db picks another database. Quit with \q (or Ctrl-D).

Scripting backslash commands

For several backslash commands, put them in a file and use ./pg run file.psql, or pass them on standard input. Inside the container: ./pg exec bash -c "printf '\\\\dn\\n' | psql -X -U postgres -d shop". Both forms were tested for this page.

A semicolon ends SQL, not a meta-command

A meta-command ends at the end of the line. SQL needs ;. If a prompt shows shop-# instead of shop=#, psql is still waiting for the rest of a statement: type ; or press Ctrl-C to throw the buffer away.

Help: \? and \h

  • \? lists every meta-command. \? variables lists the settings you can \set.
  • \h lists SQL commands; \h drop table shows the syntax of one.

Connect and look around

CommandWhat it doesExample
\lList databases, with owner, encoding and access privileges\l
\c dbConnect to another database (also \c db role)\c shop
\conninfoWho and where am I connected as?\conninfo
\dnList schemas (\dn+ adds privileges and descriptions)\dn+ shop
\dtList tables (\dt+ adds size)\dt shop.*
\dvList views\dv shop.*
\diList indexes\di shop.*
\dfList functions\df shop.*
\d nameDescribe a table, view or index: columns, indexes, keys\d shop.orders
\d+ nameAs \d, with storage, stats target and descriptions\d+ shop.orders

Most listing commands take a pattern that accepts * (any run of characters) and ? (one character), and a schema.name form. Without a pattern they show only objects in schemas on your search_path, which is why \dt alone shows nothing for the shop tables until you add shop.* or change the path (lesson 2). Add S to include system objects (\dtS) and + for more detail.

\d shop.orders is the command you will type most. Its output ends with the indexes, the foreign keys it has and the foreign keys that point at it (Referenced by:). \d+ adds the not-null constraints and storage details.

Roles and privileges: \du, \dg, \dp, \ddp

CommandWhat it shows
\du, \dgRoles and their attributes. They are the same command: \dg is an alias of \du, because PostgreSQL has only roles (lesson 3). \du+ adds descriptions.
\dp [pattern]Table, view and sequence privileges, plus column privileges and policies (lesson 4)
\ddpDefault privileges set with ALTER DEFAULT PRIVILEGES
\dn+Schemas with their privileges

Reading \dp: the Access privileges column holds entries of the form role=letters/grantor. An empty role name before the equals sign means PUBLIC. The letters are r select, w update, a insert, d delete, D truncate, x references, t trigger, m maintain. An empty column does not mean "nobody": it means the defaults apply, which is only the owner. Control how results look: \x, \pset, \timing

\x: expanded display

\x toggles between the table layout and one-line-per-column. Use it for wide rows. \x auto switches only when a result is wider than your terminal.

End any query with \gx instead of ; to expand just that result.

\timing

\timing toggles printing how long each statement took, as seen by the client (it includes the network).

The time you see will differ; it depends on your machine and on what is cached.

\pset: output settings

\pset option value sets how results are printed. Options you may want:

SettingEffect
\pset null '(null)'Show NULL as text instead of an empty cell. Strongly recommended.
\pset border 2Draw a box around the table (0, 1 or 2)
\pset format csvPrint results as CSV (also aligned, unaligned, html, wrapped, latex)
\pset pager offNever pipe long output to a pager
\pset footer offHide the “(N rows)” line
\pset linestyle unicodeUse line-drawing characters

\crosstabview and \gdesc

\crosstabview rowcol colcol turns a three-column result into a pivot table. \gdesc describes the columns a query would return, without running it.

Variables: \set and \echo

\set name value defines a psql variable. Use it in SQL as :name (raw text), :'name' (quoted as a string literal) or :"name" (quoted as an identifier). \echo prints text. \set alone lists every variable, including built-in ones such as DBNAME, USER, PORT and SERVER_VERSION_NAME.

\gset runs a query that returns one row and stores each column in a variable named after it. After select count(*) as n \gset (a query with no FROM, so the count is 1), \echo n is :n prints n is 1. \unset name removes a variable.

Settings you may want to change

VariableEffect
ON_ERROR_STOPWhen on, a script stops at the first error and psql exits with a non-zero status. Off by default. See below.
ECHOqueries prints each statement before running it; all prints everything read from a script.
ECHO_HIDDENWhen on, shows the SQL behind every \d command. A good way to learn the catalogs.
ON_ERROR_ROLLBACKWhen on, an error inside a transaction does not abort the whole transaction in an interactive session.
QUIETHide the chatter such as “Timing is on.” and command tags.
HISTSIZEHow many commands the history remembers (500 in this container).
AUTOCOMMITon by default: each statement commits by itself unless you write BEGIN.

ON_ERROR_STOP

By default, psql carries on after an error. In a script that is how half a migration gets applied without anyone noticing. Turn it on, and the script stops and psql exits with status 3. Compare the same two lines with the setting off and on (piped in from standard input):

The ./pg helper already starts psql with ON_ERROR_STOP=1 for ./pg sql and ./pg run. In a script file you can write \set ON_ERROR_STOP on on the first line.

Files, shell and the editor

CommandWhat it does
\i fileRun the commands in a file. \ir file resolves the path relative to the current script.
\o fileSend query results to a file. \o with no argument goes back to the screen. \o |command pipes them.
\copyLoad or save a table through the client: a file on your side, not the server's
\! commandRun a shell command
\eEdit the current query in your $EDITOR; the saved text runs when you exit. \ef func and \ev view edit definitions.
\p, \rShow, or clear, the query buffer
\sf func, \sv viewShow a function's or view's definition
Paths are on the machine where psql runs

When you use ./pg psql or ./pg exec psql, psql runs inside the container, so \i, \o and \copy read and write the container's files, not yours. ./pg run file.sql is the way to run a file from your machine: it feeds the file to psql's standard input.

\copy ... from works the same way in the other direction. The difference from the SQL command COPY is who reads the file: COPY makes the server read it and needs special privileges; \copy makes the client read it and sends the data over the connection (lesson 9).

\e opens the editor and runs what you save. Set EDITOR in your shell first (for example export EDITOR=nano); the container needs one installed too, so on the course container you will usually edit a file on your own machine and run it with ./pg run instead.

\gexec: run the result of a query

\gexec sends the query, then runs each value in its result as a SQL statement. It turns SQL into a code generator: write a query that produces statements, end it with \gexec.

The first query only displays its statements (it ends with ;). Replace the ; with \gexec and psql runs the two ANALYZE commands. Use format('%I') for names and %L for values, so the generated SQL is correctly quoted.

\watch: repeat a query

\watch re-runs the current query every few seconds until you press Ctrl-C. Give it an interval with i= and a limit with c=. It is the quickest way to watch activity change.

A typical use: select pid, state, wait_event from pg_stat_activity where datname = 'shop' \watch 2. (\watch 2 means every 2 seconds, which is also the default.)

~/.psqlrc: your defaults

When psql starts it reads ~/.psqlrc and runs the commands in it. This is the place for settings you always want. A good start:

Two things to know. First, the -X flag tells psql to ignore the file; the course's ./pg helper starts psql with -X, so a ~/.psqlrc on your own machine does not change course output (and the container has none). The file applies to a psql you start yourself on your host. Second, the variable PSQLRC points psql at a different file. Tested in the container: with PSQLRC=/tmp/annex_rc a \echo in the file ran and \pset linestyle unicode changed the borders; with -X neither happened.
