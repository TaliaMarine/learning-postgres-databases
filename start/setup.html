Set up your lab

You need Docker and a terminal. The course database runs in a container on your machine, so you can break it, drop it and rebuild it without consequences. Nothing is installed on your system except Docker.

about 10 minutes Docker Desktop or Docker Engine macOS · Linux · Windows (WSL 2)

1. Install Docker

Install Docker Desktop (macOS, Windows) or Docker Engine with the Compose plugin (Linux). Then check it works:

Windows

Run every command below inside WSL 2 (Ubuntu), not in PowerShell. The ./pg helper is a Bash script.

2. Get the course

Clone the repository, or download it as a zip and unpack it. Then open a terminal in its folder.

3. Start PostgreSQL 18

The first start takes half a minute: the image is downloaded, the cluster is created, and the course dataset is loaded (about 240 MB, one million analytics events). When you see ready, the database is listening on 127.0.0.1:55432 with user postgres, password course.

Port already in use?

Another PostgreSQL may be on port 55432. Run PG_PORT=55433 ./pg up instead. The helper passes the port to Docker Compose; the exercises use the helper, so they follow the port automatically.

4. Confirm it works

The count should be 200 000. Open a full interactive session with ./pg psql, type \dn to list the schemas, and \q to leave.

The ./pg helper

Every exercise and most commands in the course go through one script, so you never need to remember Docker flags. The commands you will use most:

CommandWhat it does
./pg up / ./pg downStart and stop the container. Your data is kept.
./pg psqlInteractive psql as the superuser, in database shop.
./pg sql "…" [db]Run one statement and print the result.
./pg run FILE.sql [db]Run a whole file.
./pg psql-as ROLEConnect as another role, to see what its privileges allow.
./pg check LESSON [N]Check your exercises. For example ./pg check 03 or ./pg check 03 2.
./pg solution LESSON NPrint a model solution. Try the exercise first.
./pg resetDelete all data and start again from the seeded dataset. Use this when you have changed the shop data and want it back.
./pg logsFollow the server log. Useful when something is slow or failing.
Two databases, one server

Your practice database is shop. The exercise checker never touches it: it copies a clean template for every check and throws the copy away. You can therefore experiment in shop freely and still have the checker work.

The shop dataset

Almost every lesson uses the same data. Learn its shape once here; you will see it again and again.

TableRowsWhat it is
shop.customers20 000Customers with country, status, a JSONB profile and an optional self-reference (referred_by).
shop.categories13A two-level category tree.
shop.products500Products with price, stock, text tags and JSONB attributes.
shop.orders200 000Orders across 2023–2025, with an enum status.
shop.order_items≈600 000Order lines, primary key (order_id, line_no).
analytics.events1 000 000An append-only event stream with no secondary indexes. The lessons on performance start here.

The seed is deterministic, so a result you see on your machine is the result described in the lessons. The browser playgrounds use a much smaller copy of the same tables, so plans and timings differ there; each lesson says so where it matters.

The in-browser playground

Some pages have a box marked playground. It runs a real PostgreSQL 18 inside your browser (WebAssembly, via PGlite). Nothing is sent to a server: the database lives in the page and is lost when you reload. Press Ctrl/⌘ + Enter to run what is in the box.

The playground behaves like psql: each statement runs on its own (autocommit), and a script stops at its first error. Everything before the error has already happened, so running a box that creates things a second time can fail with already exists. Use Reset data to start over. A few extensions (such as pg_trgm) and everything that needs several sessions, replication or the server's statistics are only available in the Docker database; the lessons say so where it applies.

If something goes wrong

  • “docker: command not found” — Docker is not installed or not on your PATH. Restart the terminal after installing it.
  • “not ready after 120 s” — run ./pg logs. The usual cause is a failed seed step, which the log shows.
  • Checks fail with “role already exists” — an earlier run left a lab_* role behind. Run ./pg clean-roles.
  • Anything else — see Annex E.
