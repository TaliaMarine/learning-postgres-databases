The course teaches how PostgreSQL itself works, and stops there on purpose. A lot of useful PostgreSQL work happens in extensions and external tools, or goes deeper than a lesson can. This page lists what we left out, why, and where to continue. Everything under Official documentation links to the PostgreSQL 18 manual.

How we chose what to leave out

A topic is out of the course when it needs software the course container does not have, when it belongs to a specific kind of workload, or when the right answer depends on a choice you have to make for your own system. The foundations you did learn (roles, the planner, MVCC, WAL) are what make every item below easier to learn.

Topics left out, and where to go

TopicWhat it isWhy it is not hereWhere to go
PL/pgSQL in depth PostgreSQL's procedural language: variables, loops, cursors, exceptions, dynamic SQL. Lesson 18 and lesson 19 use it, but only enough to write functions and triggers. The PL/pgSQL chapter and Server Programming.
PostGIS An extension for geographic data: points, lines, polygons, distance and containment queries with GiST indexes. Not in the standard image; it is a large subject of its own. The PostGIS project's own documentation. Start with the GiST section of Indexes, which is what it builds on.
pgvector An extension that stores embeddings in a vector column and finds nearest neighbours with specialised indexes. Not in the standard image; the techniques change fast. The pgvector project page. The extension mechanics (CREATE EXTENSION) are in lesson 26.
Citus An extension that shards tables across several PostgreSQL servers so one logical database can scale out. Needs a multi-node setup and a distribution-key design. The Citus documentation. First get comfortable with partitioning, its single-server relative.
Foreign data wrappers (FDWs) Query another PostgreSQL server, or a different system, as if its tables were local. Needs a second server and careful privilege design. postgres_fdw, and the list of additional modules.
TimescaleDB An extension for time-series data: automatic time partitioning, compression and continuous aggregates. Not in the standard image; it is a product with its own concepts. The TimescaleDB documentation. The built-in basis is partitioning and BRIN indexes.
pgBackRest A backup tool with parallel, incremental backups, WAL archiving, retention policies and restore verification. The course teaches the underlying pg_dump, base backups and WAL archiving, which it automates. The pgBackRest user guide, after lesson 23. Also: Backup and Restore.
Patroni and CloudNativePG Tools that run a PostgreSQL cluster with automatic failover: Patroni on virtual machines or containers, CloudNativePG on Kubernetes. They need a cluster manager and a consensus store; the course covers the replication they automate. Their own documentation, after lesson 24. Also: High Availability, Load Balancing, and Replication.
pg_partman An extension that creates future partitions and drops old ones on a schedule. Lesson 20 shows how to do this by hand, which is the part worth understanding first. The pg_partman project page, after lesson 20.
pgTAP A unit-testing framework written in SQL: assert that tables, columns, functions and privileges are what you expect. Not in the standard image; the course uses its own ./pg check. The pgTAP project page. The catalog queries in annex C are the raw material of such tests.
Third-party projects

PostGIS, pgvector, Citus, TimescaleDB, pgBackRest, Patroni, CloudNativePG, pg_partman and pgTAP are separate projects with their own sites, versions and release schedules. We do not link to them here because their addresses and supported PostgreSQL versions change; search for the project name and check that it supports PostgreSQL 18 before you install it.

Habits worth keeping

  • Keep a throwaway database for experiments (annex A5) and make breaking things cheap.
  • Read the plan before you add an index, and measure after (lesson 13).
  • Give every application its own role with the smallest privileges that work (lesson 5).
  • Test your restore, not only your backup (lesson 23).
  • Read the release notes before every upgrade, including minor ones.
